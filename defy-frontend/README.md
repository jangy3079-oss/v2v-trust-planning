# defy-frontend

15c 실시간 차량 시연 웹 프론트엔드입니다. Vite + TypeScript(프레임워크 없음)로 만들었습니다.

- 기본은 **샘플 데이터** 모드입니다. 화면 위쪽에 "샘플 데이터 — 실제 15c 출력 아님"이 표시됩니다.
- `?source=server`를 붙이면 서버 모드가 되고, 실제 15c 서버(`real/`)나 개발용 목업 서버(`mock/`)와 WebSocket으로 통신합니다.

## 준비

- **Node.js 24 이상.** 서버(`real/*.ts`, `mock/*.ts`)를 Node가 TypeScript 그대로 실행하기 때문입니다. nvm을 쓴다면 `nvm use`로 `.nvmrc`의 버전을 고를 수 있습니다.
- **실제 15c 서버용 Python:** torch, numpy, scipy가 필요하고, nmpc를 쓰려면 casadi도 필요합니다. `python3`가 이 패키지들이 있는 파이썬이 아니면 `DEFY_PYTHON=/path/to/python`으로 지정합니다(`real/README.md`). 정확한 패키지 목록과 버전은 확인 필요입니다.
- 이 폴더는 `v2v-trust-planning` 저장소의 `defy-frontend/`입니다. 실제 서버가 `../demo_v15c`를 읽으므로 저장소 전체를 받습니다. 별도 저장소(`cksdyd3786/defy-frontend`)와의 관계는 확인 필요입니다.

```bash
cd defy-frontend
npm install
```

## 실행

### 실제 15c 서버 (시연 기본)

터미널 두 개가 필요합니다.

```bash
npm run real   # 실제 15c 서버 (포트 8787, 환경변수 MOCK_PORT로 변경). python 경로는 DEFY_PYTHON
npm run dev    # Vite 개발 서버. /api 를 8787 로 프록시
```

http://localhost:5173/?source=server 를 엽니다. 자동 모드로 바로 시작합니다(아래 "자동 모드").

- **서버를 다시 켜야 하는 경우:** 실제 서버의 Python 브리지는 첫 자동 세션 때 `real/auto_driver.py`를 한 번만 읽습니다. `real/`을 고쳤으면 `npm run real`을 다시 시작합니다.
- **다른 주소의 서버:** `DEFY_API_TARGET=http://서버주소:포트 npm run dev`로 프록시 대상을 바꿉니다.

### 시연 빌드

```bash
npm run build     # 계약 확인 → 타입 검사 → dist/ 빌드
npm run real      # 다른 터미널
npm run preview   # 빌드 결과를 http://localhost:4173 으로 제공. /api 프록시는 개발 서버와 같음
```

http://localhost:4173/?source=server 를 엽니다. 시연 빌드에서는 개발용 도구("테스트" 드롭다운, `#debug` 창, `#frame=` 정적 프레임)가 숨겨지고, 주소에 `#debug`를 붙여도 열리지 않습니다(`src/config.ts`의 `DEV_TOOLS = import.meta.env.DEV`).

### 목업 서버 (개발용, 실제 15c 아님)

```bash
npm run mock   # 목업 서버 (기본 포트 8787)
npm run dev
```

http://localhost:5173/?source=server 를 엽니다. 목업은 계약(`src/contracts.ts`) 형식만 흉내 내며 자동 모드가 없어서 항상 직접 조종입니다(`mock/README.md`).

### 샘플 모드 (서버 없이)

```bash
npm run dev
```

http://localhost:5173 을 엽니다. 처음에는 4단계 안내가 나오고, Enter 또는 아무 키로 넘깁니다. 개발 모드에서는 오른쪽 위 "테스트" 목록에서 샘플 재생과 정적 확인 프레임을 고릅니다. 시연 빌드에서는 이 목록이 없고 샘플 재생만 나옵니다.

## 자동 모드

자동 모드를 지원하는 서버(`GET /health`의 `auto_drive_available=true`, 지금은 실제 15c 서버)에 연결하면, 시작 화면 없이 **항상 자동 모드(위험도 높음)** 로 세션을 만듭니다.

- **생성 요청:** 본문은 `{"auto_drive": true, "auto_level": "high"}`입니다. 시드는 서버가 정하고, 엔진은 기본 rule입니다. 위험도는 `src/config.ts`의 `AUTO_START_LEVEL` 한 곳에서 바꿉니다(예: `'random'`).
- **시드 표시:** 서버가 정한 시드는 주행 화면 왼쪽 아래 도크의 자동 상태 칸("자동 · 높음 · seed …")과 데이터 근거 탭의 "자동 기록" 팝오버에 나옵니다. R을 누르면 같은 시드로 다시 시작합니다.
- **가상 운전자의 이벤트:** 시나리오 1~5(1 드리프트, 2 조향 고정, 3 위빙, 4 급제동, 5 급가속)와 차로 진입(이웃차가 자차 차로로 들어옴) 중 하나를 고릅니다. 같은 키(W/A/S/D, Q/E, 1~5/0)를 사람과 같은 경로로 넣습니다.
- **사람이 개입하면 수동으로 바뀝니다.** 자동 주행 중 사람이 키나 명령을 보내면 서버가 바로 직접 조종으로 바꿉니다. 자동 상태 칸에는 주행 중 "키를 누르면 직접 조종으로 바뀝니다"가 항상 보이고, 바뀐 뒤에는 사유(사람 키 입력 / 사람 명령)와 "R을 누르면 자동 주행으로 돌아갑니다"가 보입니다.
- **R로 자동 복귀:** R을 누르면 안내부터 다시 시작하고, 안내를 끝내면 같은 시드로 자동 주행이 다시 시작됩니다.
- **직접 조종으로 시작하기:** 주소에 `?mode=manual`을 붙이면(`?source=server&mode=manual`) 자동을 지원하는 서버에서도 `{}`로 직접 조종 세션을 만듭니다. 화면에는 노출하지 않는 개발·비교용 경로입니다.
- **무작위와 시드:** 가상 운전자의 입력 순서에만 쓰입니다. 시뮬레이션 잡음(배경 흔들림·관측 잡음)은 매번 같습니다. 자동 상태 칸의 툴팁에도 같은 내용이 있습니다.
- 목업처럼 자동을 지원하지 않는 서버이거나 health 요청이 실패하면 `{}`로 직접 조종 세션을 만듭니다.

자동 세션을 눈으로 확인하는 순서:

1. `npm run real`과 `npm run dev`를 켠 뒤 http://localhost:5173/?source=server 를 엽니다. 바로 안내 4단계가 나오고, 말풍선에 "자동 모드: 안내를 끝내면 …" 한 줄이 더 붙습니다. 안내는 건너뛸 수 없습니다.
2. 안내를 끝내면 도크에 **자동 · 높음 · seed (서버가 정한 값) / 보통 주행 (첫 대기 전)** 이 보입니다. 약 10초 뒤 **다음 이벤트 대기 · 다음 이벤트까지 n초** 로 바뀝니다.
3. 이벤트를 고르면 **이벤트 중 · (종류)** 가 보입니다. 운전자가 누른 W/A/S/D는 키 그림에 **점선 하늘색 테두리**로, 사람이 누른 키는 흰 바탕으로 표시됩니다. 위빙·드리프트·조향 고정은 시작 위치까지 W/S·A/D로 옮긴 뒤 숫자 키를 누르므로, "이벤트 중"이 보이고 한동안 조향만 하다가 시나리오가 시작됩니다.
4. 아무 운전 키(예: W)를 누르면 바로 **직접 조종으로 바뀜 · 사람 키 입력** 이 보입니다. Q/E·1~5·0이나 [시나리오 해제 (0)] 버튼으로 바뀌면 사유가 **사람 명령(Q/E·1~5·0)** 입니다.
5. R을 누르면 안내부터 다시 시작하고, 안내를 끝내면 같은 시드로 자동 주행이 다시 시작됩니다.
6. 다른 창을 눌러 포커스를 옮기면 일시정지 카드가 나오고 그대로 멈춰 있습니다. 자동으로 재개하지 않으니 [재개]를 누릅니다.
7. **데이터 근거** 탭에 **입력 출처**(자동 / 직접 조종 · 사유)와 **자동 기록** 팝오버가 있습니다. 운전자의 시나리오 해제·깜빡이는 시나리오·로그 탭의 최근 로그에 기존 이벤트와 같은 모양으로 나옵니다.

## 개발용 도구 (개발 모드에서만)

- **"테스트" 드롭다운:** 샘플 재생과 정적 확인 프레임을 고릅니다. 서버 모드에서는 비활성입니다.
- **`#debug`:** 주소 끝에 붙이면 메시지 로그 창과, 목업 서버의 [오류 일으키기] 시험 메뉴가 보입니다.
- **`#frame=<id>`:** 정적 확인 프레임을 바로 엽니다.
- 시연 빌드(`npm run build`)에서는 셋 다 꺼집니다.

## 알려진 한계

- **자동 모드는 rule로만 동작하고 rule에서만 검증했습니다.** nmpc는 확인하지 않았고, 엔진(nmpc)을 고르는 UI도 없습니다.
- **실제 서버(`real/`)는 브리지 프로세스가 하나뿐이라, 명세 10.1의 nmpc 세션 격리 요구를 충족하지 못합니다.** 여러 세션을 동시에 쓰면 Python Session과 NMPC solver 상태를 같이 씁니다.
- 자동 모드 지원 여부를 보려고 서버 모드 시작 때 `GET /health`를 한 번 더 부릅니다(`?mode=manual`이면 부르지 않음). 직접 조종 세션의 생성 요청 본문은 전과 같은 `{}`입니다.
- **목업 서버는 자동 모드를 지원하지 않습니다**(`auto_drive_available=false`). 목업에서는 항상 직접 조종입니다.
- **자동 모드의 위빙은 이웃차가 자차 앞(약 25 m) 같은 차로로 들어온 뒤 시작합니다.** 위빙의 실제 흔들림은 표의 진폭보다 커서(1.2 m 단계는 한쪽 최대 약 2.6 m), 바깥 차로에서 시작하면 도로를 벗어납니다. 가운데 차로에서는 세 단계 모두 12초를 끝까지 흔듭니다(평균 폭 0.8 m 단계 1.7 m, 1.2 m 단계 3.6 m, 0.5 m 단계 1.4 m).
  - 대신 자차 바로 앞에서 흔들리므로 자차가 회피하는 경우가 많습니다(1.2 m 단계 14/18회). 최소 차체 간격은 1.15 m까지 좁아졌습니다. high, seed 7~9, 각 60분 측정에서 충돌과 도로 이탈은 0이었습니다.
  - 그래서 위빙 전에 차로 진입이 한 번 들어가는 셈입니다. 위빙에서는 깜빡이를 켜지 않습니다.
- **위빙은 드뭅니다.** 이벤트 6종 중 하나를 고르는데, 안전 확인(seed 7~11)에서 위험도 높음 50분 동안 위빙 시작은 6번이었습니다.
- **1366×768에서는 이웃차 속도 라벨이 왼쪽 아래 도크에 가려질 수 있습니다.** 이웃차가 왼쪽 차로에서 자차 앞 약 25~35 m에 있을 때입니다. 속도는 도로 위 HUD 토글로 볼 수 있습니다.
- **이웃차가 자차 앞 54 m 이상이면 차와 속도 라벨이 화면 위쪽에서 잘릴 수 있습니다.** 화면은 자차 앞 약 55 m까지 보여 줍니다.
- **"무작위"는 가상 운전자 입력 순서의 무작위입니다.** 시뮬레이션 seed는 0으로 고정이라 시뮬레이션 잡음은 매번 같습니다.
- **한 PC에서 실제 서버를 여러 개 동시에 돌리면 함께 멈출 수 있습니다.** 서버 6개를 동시에 띄운 검증에서 모든 세션이 같은 순간 약 14초 멈췄다가 끊겼고, 서버 하나씩 돌리면 문제가 없었습니다. OneDrive 동기화 폴더 안의 `real/logs` 기록 같은 환경 문제로 추정하며, 원인은 확인 필요입니다.
