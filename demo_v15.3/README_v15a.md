- v15 rule 백엔드에서 40 m 앞 이웃이 급제동하면 자차가 **28.4 s에 정지해서 약 33 s 동안 서 있었다.** k_drain 1.0이면 41 s다. 시드 0, 헤드리스로 측정했다.
- 원인은 두 가지가 겹친 것이다.
  - v14b 누적기의 반응 경보가 2 s 급제동 뒤 약 37 s 이어진다.
  - demo_v13 rule 규칙이 짧은 경보를 전제로 한다.
    - 경보 중이고 이웃이 [−10, 60] m 안이면 접근 여부와 무관하게 매 스텝 −3 m/s²로 감속한다.
    - 개입 해제 조건이 τ > 0.7 2 s뿐이라서, 경보가 끝날 때까지 "가속 중지(a = 0)" 상태로 0 m/s에 머문다.
- NMPC 백엔드는 멈추지 않았다(최저 약 20 m/s).

## 1. 바뀌는 것: rule 백엔드만 (`ego_controller.py`의 `RuleBackend`)

- **접근 판정:** closing = 종방향 접근 속도다(`closing_speed`, 앞: v_ego − v_nb, 뒤: v_nb − v_ego). **접근 중 ⇔ closing > 0.5 m/s.**
- **위험:** 반응 경보(τ_eff 경보) **그리고** dx ∈ [−10, 60] m **그리고** 접근 중.
- **진입:** 위험이면 개입 상태가 된다. 횡방향은 v13과 같다(이웃 반대쪽으로 0.5 m).
- **개입 중 종방향:**
  - 위험이고, 이웃이 앞(dx > 0)이고, TTC < 5 s이면 a = −3 m/s²(TTC < 2 s이면 −5)다. 상태는 "회피(감속)"다.
  - 위험이지만 위 조건이 아니면 a = 0이다. 뒤·옆에서 접근하거나, 앞이지만 TTC ≥ 5 s인 경우다. 상태는 "회피(가속 중지)"다. **뒤에서 접근하는 이웃 때문에 감속하지는 않는다.** 감속하면 간격이 더 빨리 줄기 때문이다.
  - 위험이 아니면 a = 0이고 해제를 기다린다. 상태는 "회피(대기)"다.
- **해제:** (τ_eff > 0.7 **또는** 위험 아님)이 **2 s 연속**이면 해제한다.
  - v13은 τ > 0.7만 봤다. 이번에는 "멀어지거나 접근이 멈추면 2 s 뒤 해제"가 추가됐다.
  - 해제 뒤 복귀는 v13과 같다: a = clip(0.5·(v_set − v), ±1.5), Y = 0.
- **새 상수(코드 전 고정):** 접근 임계 0.5 m/s, 감속 시작 TTC 5 s. 나머지(−3/−5, TTC 2 s, 0.5 m, 2 s, 복귀 이득)는 v13 그대로다.
- **NMPC 백엔드·탐지기·τ_eff·sim·k_drain은 바꾸지 않는다.**

## 4. 요약

1. **정지 문제는 해결됐다(시나리오 7 충족).**
   - 40 m 앞 이웃이 급제동해도 rule 자차가 **20/20 run 모두 멈추지 않았다**(최저 속도 중앙 12.5 m/s, 충돌 0).
   - 같은 시드에서 이전 v15 rule은 13/20 run이 정지했고, 정지 시간 중앙값은 33.1 s였다.
2. **대신 자차가 방금 이상을 보인 이웃 옆을 지나간다.**
   - 최소 간격 중앙값이 1.8 m로 v15(23.8 m)보다 작다. 시드 0~2에서 확인하니 이 최소 간격은 옆 차로에서 나란히 지나갈 때의 **횡간격**이다(종간격 0~0.2 m, 횡중심 거리 3.2~3.7 m).
   - 충돌은 없었다. v15는 정지해서 지나가지 않았기 때문에 간격이 컸다.
   - 이웃이 그 순간 자차 쪽으로 움직이면 위험할 수 있다. 이 데모에서는 시험하지 않았다(한계).
3. **불필요한 자차 반응이 줄었다.** rule 기준, v14b 반사실 대비 다음과 같다.
   - 신호 끈 차선변경: 16 → **6**/20
   - W/S 정상 가감속: 16 → **5**/20
4. **뒤·옆에서의 rule 반응도 줄었다(설계 결과, v15 판정으로는 미충족).**

   | 시나리오 | v15 | v15a |
   |---|---|---|
   | 3b 뒤에서 급가속 | 20/20 | 8/20 |
   | 4a 나란히 급가속 | 20/20 | 2/20 |
   | 4b 나란히 급제동 | 17/20 | 12/20 |

   - 이유 1: 1절 규칙은 "접근 중"(접근 속도 > 0.5 m/s)일 때만 개입하고, 뒤·옆 접근에는 감속하지 않는다.
   - 이유 2: 나란히 있다가 이웃이 가속해서 앞으로 가면 접근이 아니다.
   - v15 README 6절의 "자차 반응 있음" 기준을 그대로 적용하면 미충족이다. 기준을 바꾸지 않고 그대로 적는다.
5. **바뀌지 않은 것:**
   - 시나리오 1·2(멀어지는 종방향 이상)는 여전히 반응 경보 20/20, 미충족이다. 탐지기·τ_eff는 그대로이고, 원인(펄스 끝 잔차 부호)도 v15와 같다.
   - rule 자차 반응은 1에서 10 → 0/20으로 줄었다. 앞차가 멀어지면 접근이 아니기 때문이다.
   - 횡방향 회귀(5)는 v14b와 계속 일치한다.
   - τ_eff < τ는 348,000표본 중 0이다.
   - nmpc 결과는 v15와 같다(백엔드를 바꾸지 않았다).

## 6. 알려진 한계

- **이상 이웃 옆 통과:** 자차가 멈추지 않는 대신, 경보가 남아 있는 이웃 옆을 지나간다(횡간격 약 1.4~1.9 m). 그 순간 이웃이 횡방향으로 움직이는 경우는 시험하지 않았다.
- **뒤·옆 이상에 대한 rule 반응 감소:** 뒤에서 다가오는 이웃에는 감속하지 않는다(의도). 옆 차로로 비켜서는 동작은 "접근 중"일 때만 한다.
- **시나리오 1·2 미충족은 그대로다.** 원인은 τ_eff의 표본별 부호 규칙이다(v15 README 11절).
- **경보 지속은 그대로다.** 반응 경보는 급제동 뒤 약 39 s 남는다(시연 시나리오). 자차는 그동안 "회피(대기)" 상태로 가속을 멈추고, 위험이 사라진 지 2 s 뒤 복귀한다.
- **새 상수(0.5 m/s, 5 s)는 코드 전에 정했고, 결과를 보고 바꾸지 않았다.** 다른 값은 시험하지 않았다.
