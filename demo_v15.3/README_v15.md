## 2. 변경 1 — k_drain (회복 가속, 홀드 유지)

- **누적 구간(S 증가)과 홀드 구간은 v14b와 같다.**
  - 후보값: S* = max(0, ρS + min(e, 2θ) − ν).
  - S* > S이면 S ← S*(증가)다.
  - 마지막 증가 뒤 T_hold 안이면 S 유지(홀드)다.
- **홀드가 끝난 뒤 감소 스텝만 바뀐다:**
  - S ← max(0, S + min(e, 2θ) − k_drain·(ν + (1 − ρ)·S)).
  - k_drain = 1이면 S*와 같다(v14b).
  - k_drain ≥ 1이면 이 값은 S* 이하이고 S 이하다.
- **기본값 k_drain = 1.3.** 화면에서 `,`/`.` 키로 1.0~2.0을 0.1 단위로 조절한다. HUD에 현재 값과 "미검증 설정"을 표시한다.
- **영향 표 (`kdrain_v15.py`):** 검증 세트만 쓰고 테스트 세트는 쓰지 않는다. 성능 주장이 아니라 "손잡이가 탐지에 주는 영향 확인용"이다.
  - 데이터: 검증 정상 100대(30분)와 검증 이상(시드 400000 기저, v14와 같은 규칙).
  - 이상 유형: weave L1~L4, drift 0.03~0.2, stuck 5단계, 급성 4유형(brake_step, brake_ramp, accel_ramp, depart_fast), 각 100건.
  - 설정: 명목, p_sig 1.0. k_drain ∈ {1.0, 1.3, 1.5, 2.0}. h는 v14b 값 고정이다.
  - 지표: 오경보/30분(v11 정의, v10 정의 병기), 유형별 탐지율, 경계 전 경보율, B 경로 경보 구간 길이(검증 정상, 중앙값·p95), 펄스형 급성 뒤 τ_state 복구 시간.
  - 예산(0.3/30분)을 넘으면 넘었다고 적는다.
  - v14 캐시(`scratch_v14/private`)에 있는 검증 정상, 급성 4유형, weave L1·L2는 읽기만 한다. 나머지 유형(weave L3·L4, drift, stuck)은 같은 생성기로 `demo_v15/private/`에 새로 만든다(커밋 금지).

## 4. 변경 3 — 자차 반응용 τ_eff (종방향 "접근 방향"만)

- **e 분해:** e = e_long + e_lat. e_long = (r_a/σ_a)²는 종가속 채널이고, e_lat = (r_r/σ_r)² + (r_d/σ_d)²는 r_rel·d 채널이다.
  - 잔차는 기존 `features_v10.residuals`를 쓴다(e_score와 같은 계산). r_a = a 실측 − a 예측(1-스텝 GRU)이다.
  - **단위 테스트:** e_long + e_lat이 기존 e_score와 일치해야 한다(상대 오차 1e-9).
- **위치 구역**(dx = x_이웃 − X_자차, D = 8 m, 히스테리시스 ±2 m):
  - 앞: dx > 10이면 들어가고, dx < 6이면 나온다.
  - 뒤: dx < −10이면 들어가고, dx > −6이면 나온다.
  - 그 외는 나란히다. 시작 구역은 dx 기준이고, 경계 6~10 m 사이에서 시작하면 나란히로 둔다.
- **g (e_long 포함 여부, 매 표본):**

  | 구역 | r_a < 0 (예상보다 감속) | r_a > 0 (예상보다 가속) |
  |---|---|---|
  | 앞 | 포함 (접근) | 제외 (멀어짐) |
  | 뒤 | 제외 (멀어짐) | 포함 (접근) |
  | 나란히 | 포함 | 포함 |

- e′ = e_lat + g·e_long. 횡방향 채널과 R1·R2 규칙은 항상 포함한다.
- **S′:** 같은 누적기(같은 ν, h, ρ, T_hold, k_drain, 동결)를 e′로 따로 돌린다.
- **설계 결정 (코드 전 고정): S_eff = min(S′, S).**
  - e′ ≤ e여도 홀드가 있으면 S′ ≤ S가 항상 성립하지는 않는다.
  - 이유: S′가 더 작으면 S가 늘지 않는 스텝에서 S′만 늘 수 있고, 그러면 S′의 홀드 타이머가 새로 시작된다. 그 사이 S의 홀드가 먼저 끝나 감소하면 S′ > S가 될 수 있다.
  - min으로 자르면 τ_eff ≥ τ가 구조적으로 보장된다. 즉 자차 반응 경보는 탐지 경보보다 늘 수 없다.
  - 잘림이 실제로 일어난 표본 비율을 테스트에서 보고한다.
- τ_eff = min(0.7^(S_eff/h), τ_rule), 반응 경보 = (S_eff > h) ∨ R1 ∨ R2.
- **자차 제어기(rule/nmpc)에는 τ_eff와 반응 경보를 넘긴다.** 탐지 τ는 표시·기록용(신뢰가중 어텐션용)이다.
- **HUD:** τ(탐지)와 τ_eff(자차 반응)를 둘 다 표시한다. g = 0이면 "종방향 이상 무시 (접근 아님)"를 띄운다. 탐지 경보가 났는데 반응 경보가 없으면 로그에 "무시됨" 태그를 단다.

## 8. 요약

1. **변경 3(τ_eff)은 "멀어지는" 종방향 이상을 거르지 못했다.** 시나리오 1·2가 미충족이다(0/20). 반응 경보가 20/20 run 모두에서 켜졌다.
   - **원인은 표본마다 잔차 부호로 판단하는 규칙 자체다(측정으로 확인).** 이상 펄스가 끝나는 순간 잔차 부호가 뒤집히고, 그 표본이 "접근"으로 분류된다.
   - **앞차 급가속:** 가속이 끝날 때 GRU는 계속 가속을 예측한다. 그래서 "예상보다 감속"(r_a ≈ −0.15)으로 보이고, 앞차 감속은 "접근"이라 e_long이 포함된다. 23.6~23.9 s 사이 4표본만으로 S_eff가 h를 넘었다.
   - **뒤차 급제동:** 제동 2 s 동안 e_long은 규칙대로 1,199θ가 제외됐다. 제동이 끝나는 순간 "예상보다 가속"(r_a = +0.66)이 되어 83θ가 포함됐다(h = 3.09θ).
   - 값을 바꾸지 않고 그대로 보고한다. 개선 방향(제안만)은 11절에 있다.
2. **접근 방향 반응(3·4)은 rule에서 대부분 충족했다.** 3a·3b·4a는 20/20, 4b는 17/20이다.
   - nmpc는 3b 16/20, 4a 8/20이다. 반응 경보는 20/20 켜졌지만, NMPC 상태머신이 옆·뒤 이웃에는 회피를 시작하지 않는다(demo_v13 README에 기록된 기존 한계).
3. **횡방향 회귀(5)는 완전히 일치했다.**
   - k_drain 1.0에서 v15 탐지 τ와 v14b 데모 τ14b의 최대 차는 ≤ 1.1e-16이고, 경보열은 60/60 일치했다.
   - 기본 k 1.3에서도 이 시나리오들의 탐지 경보 길이는 1.0과 같았다(이상이 끝까지 계속되기 때문).
4. **τ_eff ≥ τ:** 모든 v15 run 312,000표본 중 τ_eff < τ는 **0**이다.
   - 잘라 내기 전 S′ > S는 실제 시나리오에서 1.08%, 임의 e′ ≤ e 시험에서 34%였다.
   - **README 4절의 min 결정이 없었다면 "τ_eff ≥ τ"가 깨졌다.**
5. **k_drain(검증 세트, 성능 주장 아님):**
   - k_drain을 올리면 급제동 뒤 τ_state 복구가 줄어든다: 1.0 → 1.3 → 2.0에서 55.0 → 40.9 → 26.9 s, 미복구 38 → 11 → 2건.

   - 검증 오경보는 29 → 27 → 24건으로 오히려 줄었고 예산 이내다.
   - 기본 1.3에서도 급제동 뒤 약 40 s 경보가 남는다.
6. **W/S 램프(변경 4)는 정상 가감속 오경보를 줄이지 못했다.** 시나리오 6d에서 탐지 경보 사건이 v15 40건, v14b 40건으로 같다(run당 W·S 각 1건).

## 11. 알려진 한계

- **표본별 부호 규칙의 결함(1·2 미충족):** 펄스형 종방향 이상이 끝날 때 잔차 부호가 반대가 되어 "접근"으로 분류된다. 개선 후보는 다음과 같다(제안만, 시험 안 함, 사전 등록 필요).
  - 부호를 순간 잔차가 아니라 최근 수 초의 **누적 속도 변화 Δv(실측 − 예측) 부호**로 정한다.
  - 또는 이웃의 실제 **상대 속도(접근 속도) 부호**로 정한다.
- **NMPC 반응 지표 오염:** 이웃이 뒤에 있을 때 fallback(a = −3)이 "반응"으로 집계된다(2-nmpc 20/20). NMPC 상태머신은 앞 이웃에만 회피를 시작해서, 3b·4a의 nmpc 반응이 낮다(demo_v13 한계 그대로).
- **경보가 오래 간다:** 기본 k_drain 1.3에서도 급제동 뒤 탐지 τ 복구 중앙값이 약 41 s(검증)다. 시연 시나리오(demo_v15.json)에서는 급제동 뒤 반응 경보가 37 s 지속됐다.
- **W/S 램프:** 0.5 s 직선 램프는 누를 때 v13보다 빠르다. 정상 가감속(W 2 s, S 1 s)의 탐지 경보는 v14b와 같았다(run당 2건). 램프만으로는 정상 페달 조작의 오탐을 줄이지 못했다.
- **k_drain은 미검증 설정이다.** 검증 세트로 영향만 확인했고 테스트 세트로 평가하지 않았다. h도 다시 맞추지 않았다.
- 신호 켠 채 이상의 사각지대, p_sig 0에서의 붕괴는 v14/v14b와 같다(바꾸지 않음).
- 합성 환경 · 직선 도로 · 시뮬레이션이다. 실제 도로 성능이 아니다.
