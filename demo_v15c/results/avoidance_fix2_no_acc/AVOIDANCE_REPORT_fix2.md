# 회피기동 검증 결과

**합성·직선·시뮬레이션. 실제 도로 성능 주장이 아니다.**

기존 demo_v15c의 탐지·누적·보정·홀드를 유지한 채 공통 Vehicle, 횡·종 회피, 복귀 참조, 화면 보간을 구현했다. [구현 전 고정 설계](DESIGN_FROZEN.md), [1단계 진단](DIAGNOSIS_PHASE1.md).

신규 320회(rule·nmpc 종+횡) + 160회 v15b 비교. 비교용 off(직진)·lateral(횡만) 모드는 2026-10-29 사용자 결정으로 삭제했다(이전 결과는 results/avoidance_fix1_ego_ramp005/ 등에 보존). 8시나리오×시드0–19, 각60초, 주입20초, 배경OFF. 20회 차이는 센서 잡음이며 다양한 운전자/도로에 대한 반복이 아니다. 저장 오류 1건만 수정했으며 결과를 보고 제어·탐지 임계값을 변경하지 않았다.

**판정(v15c-fix, 계산값):** 신규 2조합(rule·nmpc 종+횡) 320회에서 자차 중심 도로 이탈 0회, 최대 |Y| 3.60 m, 종료 시 정지 0회. rule-combined 충돌 20/160·복귀 완료 140/160, nmpc-combined 충돌 20/160·복귀 완료 140/160. 충돌이 남은 시나리오(아래 표)는 막은 것으로 세지 않는다.

## 차선·도로 유지: 충돌 수만으로 성공 판정 불가

도로는 중심0, 3차로×3.5m이므로 |Y|>5.25m는 자차 중심 자체가 도로 밖인 경우다. 차체 일부 이탈보다 보수적인 집계이며 안전 통과 기준을 새로 만든 것이 아니다. 충돌 후 물리 충격은 모델링하지 않고 궤적을 계속 적분한다.

| 조합 | 중심 도로 이탈 run/160 | 최대 \|Y\| m | 60초 시점 완전 정지 run |
|---|---|---|---|
| rule-combined | 0 | 3.50 | 0 |
| nmpc-combined | 0 | 3.60 | 0 |
| v15b-nmpc | 0 | 4.88 | 0 |

v15c-fix 이전(Astra 구현)에는 기존 이득(ω=1)·4초 참조가 플랜트 조향 변화율 상한(25 m/s에서 0.0054 rad/s)을 크게 넘는 명령을 내 변화율 포화 진동으로 발산했다(최대 |Y| 241 m). v15c-fix는 플랜트는 그대로 두고, 참조를 그 한계 안으로 설계하고(거리 기반 5차, 요가속 ≤ 0.6·0.05 rad/s²) 추종 이득을 ω=0.4로 낮추며 횡목표를 차선 중심/중심±0.5 m로 제한했다. 이 변경은 실패를 본 뒤 사용자 지시로 한 수정이며 사전 고정 설계가 아니다.

v15c-fix2(2026-10-29, 사용자 결정): 이웃 차량 한계(요가속 0.05rad/s²)는 그대로 두고 **자차 Vehicle만 0.3rad/s²(합성 설정값)**로 올렸다. 정책은 종·횡 연동으로 바꿨다: TTC≤4이고 옆 차로가 비면 바로 차선변경, 제동은 횡 이동으로 이웃 차체를 벗어날 때까지 범퍼 간격 2m를 지키는 최소 감속(이웃 제동 관측 a_obs 반영, 단계 상한 0/−5/−8), 횡으로 벗어나면 제동 해제·속도 회복. 뒤차 단독 위협은 TTC≤4에서 +3m/s² 가속.

## 물리 지표와 사전 기준 판정

모든 적용 서브스텝을 집계. normal은 비상 단계가 아닌 구간 전체(평상·회피·복귀 포함)를 보수적으로 검사했다. jerk는 100Hz 적용 가속 차분, v15b는10Hz 차분이라 대역이 다르다.

슬립은 모델의 속도 방향과 동일 시각 heading의 일치 검사다. 기구학 모델의 구조적 성질이며 실제 타이어 슬립 검증이 아니다. v15b의 전진 Euler 시작 heading, 새 모델의 중점 heading에 대응한다. 10Hz 끝 heading 차이는 별도 열로 공개했다. v15b에는 비상 단계가 없어 emergency=0이다.

## 동일 동작·보존·화면 확인

- 독립 Vehicle 두 개에 같은 키보드 차선변경+제동 명령600개를 넣은 궤적 최대 차이: **0.0e+00**, a/a_lat/jerk를 포함한 적용 지표 사전도 일치(허용1e−9).
- 극한 입력의 횡가속 최대 7.99999639m/s², 조향 변화율 초과 1.78e-15rad/s(부동소수 오차).
- 보호 대상 23개 SHA-256 일치: v15b 코드, 원본 planning/Config 등, v15c detector.py/accum.py. 고정 관측의 탐지/누적 반복 출력 일치.
- 실제 Pygame 루프를 dummy 디스플레이에서 실행해 C 모드/B 엔진 전환·보간·회전 렌더링을 확인했다. 실디스플레이의 지속60FPS 성능은 측정하지 않았다.

## 알려진 한계

- NMPC 내부 예측에는 새 플랜트 액추에이터 지연/변화율 상태가 없다(원본 그대로). 그래서 v15c-fix는 NMPC의 조향을 플랜트에 직접 넣지 않고, NMPC를 계획기로 쓴다: 가속은 NMPC 값, 횡은 NMPC 지평 끝 Y의 정책 경로 대비 편차(>0.25 m)를 차선 격자에 스냅한 목표로 같은 실행 가능 참조·추종기에 넘긴다. 즉 NMPC 횡 결정의 해상도는 0.5 m 격자이고, NMPC 최적해 그대로의 궤적이 아니다.
- v15b 전후 비교는 기존 누적기와 이웃 플랜트도 다른 묶음 비교다. 신규 2조합(rule·nmpc)은 같은 플랜트·누적기를 쓰는 통제 비교다. 이전 v15b 충돌 검사는10Hz 상태를 보간하므로 신규100Hz 검사와 완전히 동일하지 않다.
- 정상 횡가속4 기준 또는60초 내 복귀 미달은 위 표에 그대로 남겼다. 결과를 보고 임계값을 바꾸지 않았다. 미회피/미복귀/충돌 run은 성공으로 세지 않았다.
- 저속/정지에서는 속도별 횡가속 한계만으로 큰 조향각이 허용된다(약1.52rad). 별도 기계적 조향각 상한은 이번 고정 설계에 없었다. 정지 시 v≥0 클립으로 가속도가0으로 전환되며 큰 저크가 생긴다. 이 역시 자연스러움의 한계다.
- 실제 이웃 x/heading 및 잡음 관측 y/v/r을 쓰고 이웃 한 대만 있다. 배경OFF, 직선, 합성 입력, 신호 관측 가능 가정이다. 초기중심간격과 범퍼간격은4.5m 차이난다.
- 새 물리 모델은 기존 위치 직접가산 주입을 명령으로 바꿨으므로 drift/stuck/정상 차선변경의 탐지 결과도 달라질 수 있다. 탐지기를 재보정하지 않았다.
- 기존 docs/ 웹 명세 및 README_preavoid.md는 변경 전 계약/설명이며 새 모드·입력 단위·충돌 기하와 다르다. 이번 작업에서 웹 API는 구현하지 않았다.
