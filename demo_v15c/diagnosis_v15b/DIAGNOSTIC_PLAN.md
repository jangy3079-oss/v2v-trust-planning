# 1단계 진단 실행 계획 — 실행 전 고정

2026-10-28. **합성·직선·시뮬레이션**. 진단 대상은 사용자가 명시한 demo_v15b.
기존 demo_v15c는 다른 누적기 버전으로 이미 존재하므로 덮어쓰지 않는다.
이 폴더에는 관측용 하네스와 결과만 추가한다. 원본 app/sim/controller/planning/Config/탐지/보정/홀드/누적기 코드는 수정하지 않는다.
2단계 설계·구현 및 3단계 20회 검증은 사용자의 진단 확인 뒤 진행한다.

## 고정 에피소드 5개

모두 기존 기본값 σmeas=.1, 방향지시등 가정 ON, 배경 ON, 자차/이웃 초기속도25m/s, 60초, 주입20초.
초기 간격은 중심 간격이다. 같은 5개를 NMPC로 측정하고 rule도 같은 조건으로 실행해 종방향 반응 존재 여부를 비교한다. 탐지 실패/회피 미개시도 그대로 기록하고 다른 사례로 교체하지 않는다.

## 기록과 지표

- 10Hz 모든 행: 자차 전/후상태, 적용입력(직전 호출의 제어출력), 새 제어출력, τeff/경보, 이웃 참상태, target_y/current_v_cmd/상태머신, fallback, 풀이시간, 충돌·간격.
- 물리량: 적용δ, r=Δθ/dt, a=Δv/dt, a_lat=v_before*r, jerk=Δa/dt, 조향변화율=Δδ/dt. 절댓값 p50/p90/p99/max, 부호가속 min/max.
- slip: 위치차분의 방향 − 해당 전진오일러 스텝의 시작 heading. 종료heading과 비교한 값은 시간정렬 오차로 별도 보고하고 타이어 슬립이라고 부르지 않는다.
- 구간: 전체, 주입뒤(20~60s), 회피(AVOIDING 또는 rule engaged), fallback. 미개시는 N/A.
- 속도기준/목표횡위치 변화시각, τ회복 뒤 복귀 여부, 100ms 초과 풀이 횟수.
- 제약 슬랙은 성공 풀이의 Opti.debug.value를 읽기만 하여 첫 스텝·최대값 기록. 예측상태가 실제상태로 대입되는지 소스와 적용입력 재계산으로 확인.
- 렌더링은 소스 검사: 60FPS 목표/10Hz 상태갱신, 보간 유무, 헤딩회전, 좌표 스케일.
- 수동 보조 진단은 별도 bg=False, 25m/s, D3초·W2초·S2초 입력의 고정 예시. 주5개 평가에 섞지 않는다.
- 결과 해석용 임계(|a_cmd|<.1을 거의0, |a_lat|>8, 차분헤딩오차>5°)는 보고용이며 제어기에 적용하지 않는다.
- 원시 궤적·UAH 요약값에 의존한 로그는 private/에 두고 commit 대상에서 제외한다.

## 사용자 확인에 따른 대상 추가 (실행 이력 보존)

사용자가 "15c에 회피기동을 넣는것이 목표"라고 확인했다. 기존 v15c를 새 기능의 기준으로 삼고 현재의 누적기/탐지 설정을 유지한다. 이미 실행된 v15b 측정은 비교 자료로 보존하고, **시나리오·시드·계측 정의를 전혀 바꾸지 않고** 같은5개를 기존 v15c에서도 실행한다. v15c가 주 진단 대상이다. 진단 폴더명은 최초 생성 경위를 보존하기 위해 그대로 둔다. 기존 sim.py와 ego_controller.py는 b/c 간 동일하며 앱의 물리/제어 호출부도 동일하다.
