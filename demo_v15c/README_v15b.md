> **합성 환경 · 직선 도로 · 시뮬레이션.** 실제 도로 성능이 아니다. 방향지시등 신호는 가정이다.
> **변경·판정 기준 고정 시각: 2026-10-28 15:21.** 1~4절은 코드 수정 전에 고정했다. 결과는 5절 이후에 추가만 한다.
> **출발점:** `demo_v15a/` 전체 복사(private·logs·results 제외). v15a README는 `README_v15a.md`, v15 README는 `README_v15.md`로 보존했다.
> v15a의 rule 백엔드(접근 중일 때만 감속), τ_eff(종방향 접근 방향만, S_eff = min), 탐지기 GRU·R1·R2는 그대로다. `demo_v15a`, `demo_v15`, `demo_v13`, `scratch_*`, `v2v_trust_planning/src`는 수정하지 않는다.

## 0. 왜 바꾸나 (v15a 측정, 탐색)

- v15a에서 직접 조작하면 이상을 넣지 않아도 **τ 탐지 평균이 0.04~0.10이고, 경보가 시간의 96~99% 켜져 있었다.** 조작 패턴은 20 s마다 W 1~2 s, 15 s마다 A/D 0.5 s였다.
- 원인: 키 입력의 GRU 예측 오차가 위빙 L2보다 크다.
  - W(+4 m/s², 0.5 s 램프)의 e p99는 6.2θ, A/D는 0.63θ다.
  - 위빙 L2의 e p99는 0.14θ다.
  - v14b 누적기는 ν가 0.022θ로 낮아서 이 오차를 계속 쌓는다.
- k_drain 2.0으로 올려도 τ 평균은 0.16이었다. 키 입력만 완화하면 τ 평균 0.67, 경보 46%였다.
- 그래서 **키 입력 완화와 누적기 교체를 함께** 한다(사용자 선택 2).

## 1. 변경 A — 키 입력 완화 (`sim.py` 상수)

| 상수 | v15/v15a | v15b |
|---|---|---|
| W 목표 가속 `A_MAX` | +4 m/s² | **+1.5 m/s²** |
| S 목표 감속 `B_MAX` | −8 m/s² | **−3 m/s²** |
| W/S 램프 `A_RAMP_T` | 0.5 s | **2.0 s** |
| A/D 요레이트 램프 `R_RAMP` | 0.10 rad/s² | **0.05 rad/s²** (상한 `R_MAX` 0.05 rad/s 그대로) |

- 이상 주입(1~5)은 그대로다. 급제동 −6 m/s², 급가속 +3 m/s²다.
- 조향이 느려졌으므로 검증용 차선변경 키 누름 시간은 이 sim에서 다시 정한다.
  - 규칙: D를 누르는 시간을 0.1 s 간격으로 바꿔 가며, 최종 횡이동이 3.5 m에 가장 가까운 값을 고른다.
  - 종료 시각은 최종 위치 ±0.1 m에 들어오는 시각이다.
  - 배경 잡음 없이 시드 0에서 측정한다.
  - 이것은 시나리오 정의이며, 탐지기와는 무관하다.

## 2. 변경 B — 누적기를 v14 B-W로 교체 (`accum.py`)

- **v14 선택안 B-W** = leaky · τ_floor 0.9 · T_r 2 s · cap 2θ · 의도 구간 동결 · 홀드 없음.
  - ν = θ·ln 0.9 / ln 0.7 = 0.2954θ, ρ = exp(−0.1/2).
  - S ← max(0, ρS + min(e, 2θ) − ν). 감소 스텝은 k_drain 식(v15 2절)이다.
- **h는 v14 결과 파일 값 그대로다(재보정 없음).** `scratch_v14/results/eval_v14.json` b_variants:
  - 명목: 신호 가정 ON(p_sig 1.0) 0.2580θ, OFF(p_sig 0.0) 18.154θ
  - σ_meas 0.3: ON 0.3814θ, OFF 19.550θ
- **k_drain 기본 1.0**(v14에서 검증한 값). 손잡이 `,`/`.`(1.0~2.0)는 남긴다. 1.0이 아니면 "미검증 설정"으로 표시한다.
  - v15의 기본 1.3은 v14b 누적기용이었다. B-W는 이미 빨리 비워지므로 v14 값을 쓴다.
- **v14에서 알려진 B-W 성질(테스트, 명목, p_sig 1.0):**
  - weave_L2 16%, 오경보 0.15/30분, 급제동 뒤 τ 복구 약 3.5 s
  - 신호 켠 채 이상에서는 사각지대가 있다
  - 이번에 다시 평가하지 않고 인용만 한다.
- τ_eff(S′, S_eff = min(S′, S))와 위치 구역·g는 v15와 같은 코드다(파라미터만 B-W).

## 3. 검증 (헤드리스, 시드 0~19, 20회; `validate_v15b.py`)

### 3.1 주 판정 — 직접 조작에서 신뢰도 회복 (새)

- **M1:** 20 s 주기로 W 2 s, 15 s 주기로 A 0.5 s → D 0.5 s. 이상 없음. 15~120 s를 본다.
- **M2:** 20 s 주기로 W 2 s → 뗌 → S 1 s. 이상 없음.
- 이웃 40 m 앞, 자차 rule이다.
- **판정(M1·M2 각각):**
  - 탐지 경보가 켜진 시간 비율의 run 중앙값 ≤ **5%**
  - τ 탐지 < 0.8인 시간 비율의 run 중앙값 ≤ **10%**
- 같은 패턴을 v15a(현재 데모, 거친 키 입력 + v14b 누적기)로도 돌려 나란히 보고한다.

### 3.2 회복 시간
- 40 m 앞 급제동(키 4) 뒤, 펄스 종료부터 τ 탐지 ≥ 0.8(1 s 유지)까지의 시간을 잰다.
- **판정:** run 중앙값 ≤ **10 s**. 급가속(키 5)은 보고만 한다.

### 3.3 v15/v15a 시나리오 1~7
- 같은 정의, 같은 판정으로 다시 돌리고 보고한다(v15 README 6절, v15a README 2절).
- 시나리오 6은 키를 쓰므로 sim이 다르다. 비교 대상은 v14b 데모 반사실(v13 sim) 그대로다.
- **횡방향 회귀(5)는 기준을 바꾼다.** 누적기가 B-W이므로, k_drain 1.0의 v15b τ 탐지가 **v14 데모(`scratch_v14/app_v14.py`의 τ14)**와 일치해야 한다(최대 차 < 1e-9). 주입 강도를 같게 맞추고 키는 쓰지 않는다.

### 3.4 단위 테스트 (`test_v15b.py`)
- e 분해 합 = 기존 창 e_score
- k_drain 1.0 누적기 = `scratch_v14/accum_v14.trace`(v14 캐시, 명목·σ_meas 0.3 × p_sig 1.0/0.0, 51개씩)
- S_eff ≤ S

- **예상과 다른 결과도 그대로 보고한다.** 상수나 판정을 결과를 보고 바꾸지 않는다.

## 5. 요약

1. **이상이 끝나면 신뢰도가 다시 오른다.**
   - 40 m 앞 급제동 뒤 τ 탐지 ≥ 0.8 회복은 중앙 **4.1 s**(p90 4.2)로 판정 충족이다. v15a는 43.5 s였다.
   - 급가속 뒤는 **2.1 s**다. v15a는 21.3 s였다.
2. **W/S 조작에는 경보가 나지 않는다.**
   - M2(W/S만)의 경보 시간은 **0%**, τ < 0.8 시간은 0%로 판정 충족이다. v15a는 95%였다.
   - 시나리오 6d(W/S 정상 가감속)의 탐지 경보 사건은 v14b 반사실 40건에서 **0건**이 됐다.
3. **M1(W + A/D 조향)은 미충족이다.** 기준은 바꾸지 않는다.

   | 지표 | v15b | 기준 | v15a |
   |---|---|---|---|
   | 경보 시간 | 7.9% | ≤ 5% | 99% |
   | τ < 0.8 시간 | 31.9% | ≤ 10% | 99% |

   - **원인은 누적기가 아니라 v12 횡방향 규칙이다.**
     - τ < 0.8 표본의 최소 성분: R1 67%, R2 31%, 누적기 2%
     - 경보 표본: R2 87%
   - **M1 패턴 자체가 차를 차로 중심에서 벗어나게 한다.** A 0.5 s → D 0.5 s를 반복하는 열린 조작이고, sim에 자동 차로 유지가 없다.
     - M1: |d| 중앙 **1.01 m**, 1 m를 넘는 시간 51%
     - 입력 없음·M2: 0.16 m
   - 즉 이 패턴은 정상 조작이 아니라 실제 횡방향 표류다. R1(오프셋 누적)과 R2(경계 도달 예측)는 정의대로 반응했다.
   - 사전 등록한 M1 패턴이 "정상 조작"을 대표하지 못했다는 점을 한계로 남긴다.
4. **시나리오 1~7:**
   - 정지 확인(7)은 충족했다. 0/20 정지, 최저 속도 중앙 15.1 m/s, 충돌 0이다.
   - 3a는 충족했다.
   - 1·2(멀어지는 종방향 이상의 반응 경보)는 여전히 미충족이다. τ_eff의 표본별 부호 규칙 문제다.
   - 3b·4a·4b의 rule 반응은 v15a와 비슷하게 낮다(설계).
5. **횡방향 회귀:** k_drain 1.0의 v15b τ와 v14 B-W 데모 τ14의 최대 차는 ≤ 2.6e-15이고, 경보열은 60/60 일치했다(충족).
6. **τ_eff ≥ τ:** 360,000표본 중 위반 0이다. 잘린 표본은 0.07%다.

## 6. 정정 (v15 README 8절 4번, v15a README 5절 마지막 줄의 수치)

- v15 `test_v15.py`의 "임의 e′ ≤ e" 시험은 **마스크를 두 번 따로 뽑아서 일부 표본에서 e′ > e(최대 2e)가 섞였다.**
- 그래서 그때 보고한 "잘림 전 S′ > S 34%"는 잘못된 입력으로 낸 수치다.

## 8. 알려진 한계

- **작은 지속 이상 탐지 감소:** 누적기를 v14 B-W로 바꿔서 v14b의 weave_L2 탐지(테스트 88%)를 포기했다. v14 B-W는 테스트 16%였다(인용).
- **조향을 오래 대면 경보가 난다(정상 동작).** 직접 조작에서 A/D로 차로 중심을 벗어난 채 두면 R1·R2가 경보한다(M1). 차로 중심으로 되돌려 주는 조작은 시험하지 않았다.
- **키 입력이 느려졌다.**
  - W +1.5 m/s², S −3 m/s², 2 s 램프다. 급하게 세우려면 이상 주입 4(−6 m/s²)를 쓴다.
  - 차선변경은 D를 약 3 s 누르고 있어야 한다(측정).
- 시나리오 1·2 미충족, 신호 켠 채 이상의 사각지대, p_sig 0에서의 붕괴는 이전 버전과 같다.
- 합성 환경 · 직선 도로 · 시뮬레이션이다.
